## O que é um MVP?

> **MVP significa Produto Mínimo Viável.** Não é o sistema completo. É a **menor versão da solução capaz de demonstrar que a proposta central funciona**.

Um bom MVP:

- resolve **uma parte clara** do problema;
- possui **pelo menos um fluxo principal funcionando de ponta a ponta**;
- é **viável** de ser construído pela equipe no prazo da disciplina;
- pode ser **testado** e **validado**.

---

## O que obrigatoriamente estará no MVP?

Com base nos requisitos funcionais e nos critérios de aceite definidos para o ObraFácil, o MVP deverá conter:

- Cadastro de obras públicas;
- Consulta das obras cadastradas;
- Pesquisa de obras por nome ou identificador;
- Visualização dos detalhes de uma obra;
- Apresentação do andamento e percentual de execução;
- Atualização das informações das obras pelos gestores;
- Área de consulta pública;
- Apresentação das informações financeiras das obras;
- Apresentação da situação atual das obras;
- Apresentação de prazos e datas;
- Dashboard do gestor com indicadores das obras.


## O que NÃO estará no MVP?

Para manter o escopo do MVP compatível com os requisitos definidos, não serão incluídos:

- Aplicativo mobile;
- Integração com mapas;
- Integração com APIs externas;
- Notificações por e-mail;
- Inteligência Artificial;
- Análise preditiva;
- Integração com sistemas governamentais externos;
- Recursos avançados de Ciência de Dados.

Requisitos futuros a serem implantados. 

## Fluxo mínimo que deverá funcionar

_Adapte o fluxo genérico abaixo para a solução da equipe._

```
Cidadão acessa a área pública
          ↓
Pesquisa pelo nome ou identificador
          ↓
Sistema localiza a obra
          ↓
Exibe os detalhes
          ↓
Situação + andamento + prazo
+ localização + informações financeiras
```

## Riscos

_O que pode impedir a entrega do MVP? Como a equipe vai reduzir esses riscos?_

| Risco | Plano de ação |
|---|---|
|Falta de conhecimento técnico da equipe |Dividir as tarefas entre os integrantes e pesquisar as tecnologias utilizadas. |
|Dificuldade na implementação do banco de dados |Utilizar SQLite, por ser simples e adequado ao escopo do MVP. |
|Atraso no desenvolvimento das funcionalidades |Priorizar as funcionalidades de alta prioridade e acompanhar o cronograma semanalmente.|
|Problemas na integração entre interface e banco de dados |Realizar testes durante o desenvolvimento de cada funcionalidade, evitando deixar a integração para o final. |
|Falta de tempo para concluir todas as funcionalidades |Concentrar o desenvolvimento inicialmente nas funcionalidades essenciais definidas para o MVP. |
|Alterações ou problemas durante os testes|Realizar testes frequentes e corrigir os problemas encontrados antes da apresentação final.|
